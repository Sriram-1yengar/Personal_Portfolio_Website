## Context

Mid-market companies rarely lose procurement money on the headline contracts — they
lose it on the long tail of SKUs where the same part is bought at five different
prices across teams and quarters. That signal is buried in messy line-item exports:
inconsistent descriptions, unit mismatches, no clean supplier key.

## Problem

Build something that turns a raw spend export into a ranked list of "you are
overpaying here, and here is the cheaper plan" — without a six-month data-cleanup
project first.

## Approach

- **Ingestion.** A Python pipeline normalizes line items into a PostgreSQL schema:
  supplier resolution, unit-of-measure conversion, and description cleanup so the
  same physical item collapses to one row.
- **Variance detection.** A fine-tuned open-source LLM classifies free-text SKU
  descriptions and flags items whose realized unit price has high dispersion
  relative to peers. Fine-tuning on labeled examples beat few-shot prompting on
  the domain vocabulary and kept inference cheap enough to run locally.
- **Optimization.** The flagged items feed a linear-programming model
  (minimize spend subject to demand, supplier capacity, and switching constraints)
  that outputs a concrete reorder plan.
- **Delivery.** A Streamlit dashboard with Plotly views: spend by category,
  variance leaderboard, and the before/after of the optimized plan.

## Architecture

```
spend export ─▶ ingest & normalize (Python) ─▶ PostgreSQL
                                                   │
                                 fine-tuned LLM ◀──┤  classify + flag high-variance SKUs
                                                   ▼
                              LP optimizer (PuLP) ─▶ purchasing plan
                                                   ▼
                                     Streamlit + Plotly dashboard
```

## Status

Ingestion pipeline and schema are built. LLM fine-tuning and the optimizer are in
progress; the dashboard is scaffolded. Writing up results and a public demo next.
